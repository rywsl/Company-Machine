## 目标

实现 ChangeSet 的受理与验证：宪法拒绝、基线过期、控制面 commit、V1/V2、声明与实际一致、V3、风险分级（运行受保护的 `risk.mrl`）、V4、跨 runtime 复核。

## 必读（读完再写代码）

- governance.md 5.4（受理的 7 步，前 5 步失败不插行）
- governance.md 4.4 与 5.6（diff 事实的精确定义、`score_risk`）
- governance.md 5.7（验证的 10 步，rejected 不抛错）
- governance.md 5.8（复核规则）
- `spec/mrl/governance/risk.mrl` 全文

## 步骤

```bash
uv run python tools/harness.py task start M3-02
uv run python tools/harness.py pytest tests/acceptance/m3/test_m3_02_changesets.py
```

1. 写 `diff_facts`（纯函数）并单独测试：同一输入在任何平台上得到同样的规范 JSON。
2. 写 `score_risk`：用 `mrl.rules` 运行 `risk.mrl`；`unscored` 或结果不完整 → `RISK_UNSCORED`。
3. 写 `propose`：按 5.4 的顺序检查，再 `commit-tree` 创建 epoch commit 与 `refs/changesets/<id>`。
4. 写 `advance(draft)`：verifying 的 10 步；每个 rejected 写报告与事件后返回。
5. 写 `add_review`、`approvals`、`withdraw`、`get`、`list`；CLI `factory changeset ...`。
6. 写 `tests/system/test_governance_changesets.py`，再跑验收。

## 错误示范与正确示范

**规则没覆盖就给个默认等级**

```python
# ✖ tier = 'T1'
# ✔ raise FactoryError('RISK_UNSCORED', ..., changes=unscored)  # 新规则由人写进 risk.mrl
```

**相信文档里的 risk_tier**

```python
# ✖ tier = doc['spec']['risk_tier']
# ✔ 受理时删除它；等级只来自 diff_facts + risk.mrl
```

**读复核意见的文字**

```python
# ✖ if '同意' in review.note: approve()
# ✔ 只数不同 runtime、摘要仍匹配的 approve
```

## 规范没写到时

- `risk.mrl` 受保护，你不能改它；觉得规则不对就写 journal。
- 比较字段用深度相等；YAML 注释与键顺序不算变化。

## 不要做

- 不要修改受保护文件（`plan/protected.lock` 登记的规范、验收测试、夹具、harness）。hook 会拒绝；绕过也会被 `lock --verify` 发现。
- 不要新增依赖，不要调用任何 LLM API，不要 `shell=True`，不要在 `base.py` 以外读时钟或生成随机数。
- 不要实现后续任务的功能；碰到“下一步才需要”的东西，按规范的“不做什么”表拒绝。

## 卡住时

规范有歧义、规范与验收测试矛盾、或同一验收项连续失败 5 次：停止修改代码，按 `plan/README.md` 第 5 节写 `plan/journal/<日期>-M3-02.md`（现象、已尝试、你认为规范应当怎样），然后

```bash
uv run python tools/harness.py task block M3-02 --reason "<一句话>"
```

不要改验收测试来“修好”它，不要猜一个接口。
