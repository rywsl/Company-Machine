# M12-03 常驻实例：调和、恢复、命令行、Daemon 接线

- 状态：未开始。依赖 M12-02 完成后才能 `task start`。
- 规范：`spec/system/instances.md`、`plan/design-resident.md`。
- 允许修改：见 `plan/tasks.yaml` 中本任务的 `paths`。
- 验收测试：`tests/acceptance/m12/test_m12_03_resident.py`（8 个）。共用夹具 `tests/acceptance/m12/instance_world.py`。
- 本任务的 `regress` 先忽略后续任务的验收：`tests/acceptance/m12/test_m12_04_emit.py`、`tests/acceptance/m12/test_m12_05_ingress.py`、`tests/acceptance/m13`。

## 要做什么

- `instances.md` 5.5：`reconcile` 启动、健康检查、退避重启、`restart.max` 后 `crashed` 并开 `instance` 唤醒票、epoch 变化时替换、`INSTANCE_INVALID` 每个工位与摘要只报一次。
- 5.6：`recover`；5.8：常驻实例的出网主体 `inst-<id>`；`/factory/state/<工位名>` 跨实例保留。
- 3.4 命令行 `factory instance list|restart|stop`；3.5 MCP `instance_list` 与控制台 `/instances`。
- 5.9 `Daemon` 接线：`daemon.instances`、`start` 时 `recover`、调度前 `reconcile`、`TickReport.instances`、`shutdown` 只关闭不停止常驻实例。

## 不要做

- 不要在实现里使用验收或夹具里的工位名、机器名、配方名、路由名、Agent 名、秘密名作为常量或分支条件。
- 不要把秘密值、令牌、入站请求体写进事件、日志、job 行或控制台页面。
- 不要提前做 M13 的 Agent（`deliver: agent`、`mao.agents`）。
- 常驻实例的主进程端口不发布、不被转发；外部消息只经入站网关写进收件目录。
- 不要修改受保护的规范、验收测试、夹具与替身；不要新增第三方依赖；不要调用模型 API；不要 `shell=True`。
- 验收与规范矛盾时写 `plan/journal/` 并 `task block`，不要猜。
