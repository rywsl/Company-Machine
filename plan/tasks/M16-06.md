# M16-06 厂长操作面与闭环验收

- 状态：未开始；M16-05 完成 后进入实现。
- 规范：`spec/system/assets.md` 第 3.4、5.1–5.8、6–9 节及全部组件增补；`plan/design-assets.md`；本任务在 tasks.yaml 引用的组件增补。
- 允许修改：以 `plan/tasks.yaml` 的 paths 为准；规范、验收和夹具为冻结输入。
- 验收：`tests/acceptance/m16/test_m16_06_surface.py`（9 个）；夹具 `tests/acceptance/m16/asset_world.py`。

## 要做什么

- 按规范提供完整 CLI/MCP，复用同一服务函数和错误码；JSON 参数/返回与 by 身份要逐项一致。
- shared 只读；agent 只能贡献自己 scope 的候选；foreman 可组织、试验、评估、晋升和接管。授权/释放/任意磁盘包操作不进 MCP。
- 仅给启用 M16 的常驻厂长复用现有 agent_send/remind，身份固定 foreman；旧工具表、worker 产线允许列表和厂长 run_start 限制不变。
- 常驻/会话厂长的 charter 给出最短使用指导：正式知识和临时记忆分开，使用现有正常工作收证据，未知条件保留为问题。
- 不改宪法、结构治理或人的 M15 产线确认；厂长可以通过既有委托、Agent 协作和已授权契约完成资产工作。
- 闭环验证候选→正常工作→证据→正式指针；全量回归、M16 零跳过、阶段门继承旧检查。交接日志记录真实边界。

## 不要做

- 不要为操作面补一套模型服务、Web 页面、特殊影子运行模式。
- 不要把静态包校验、假 CLI 验收或任务完成当真实视频/交易/工厂能力认证。
- 不新增依赖，不在控制面调用模型，不使用 shell=True，不修改既有迁移或受保护输入。
- 规范与验收冲突时按 AGENTS.md、plan/README.md 第 5 节记录并暂停受影响工作，不猜接口。
