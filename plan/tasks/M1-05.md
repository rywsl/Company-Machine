# M1-05 factoryctl 与控制通道（CtlServer）

- 状态：未开始。依赖：M1-04；所属里程碑的前置阶段门必须已通过。
- 规范：`spec/system/README.md` 第 4.6 节；`spec/system/factoryctl.md` 全文。
- 允许修改：`src/mao/ctl/**`、`src/mao/errors.py`、`tests/system/**`。
- 验收测试：`tests/acceptance/m1/test_m1_05_factoryctl.py`（8 个测试，受保护）。模块不存在时整个文件跳过；实现之后必须零失败、零跳过。

## 目标

实现沙箱内的单文件客户端 `src/mao/ctl/factoryctl.py`（Python ≥ 3.8、只用标准库、不 import mao），以及宿主侧的 `CtlServer`（文件邮箱，不开端口）。

## 必读（读完再写代码）

- factoryctl.md 3.2（命令名锁定，M2 的 `receipt`、`--label` 在 M1 是未知参数）
- factoryctl.md 4.1–4.6（全部文件格式）
- factoryctl.md 5.4（poll_once 的 5 步与后台线程兜底）
- factoryctl.md 5.6（harvest 的规则）

## 步骤

```bash
uv run python tools/harness.py task start M1-05
uv run python tools/harness.py pytest tests/acceptance/m1/test_m1_05_factoryctl.py
```

1. 先写 `factoryctl.py` 的参数解析与 5.1 的虚拟路径映射；未知子命令、缺参数、`--meta` 不是 `KEY=VALUE` → 退出码 2。
2. 实现只读命令（`inputs`、`contract`、`budget`），再实现 `submit`、`log`、`fail`、`harvest`。所有写入先写 `.part` 再 `os.replace`。
3. 实现请求/响应（`check`、`approval request`）：写请求、每 0.2 秒看响应、超时退出 1。
4. 写 `src/mao/ctl/server.py` 的 `CtlServer` 并在 `mao/ctl/__init__.py` 再导出。`poll_once` 不吞异常；后台线程兜底写 `CTL_HANDLER_ERROR` 响应并记日志。
5. `tests/test_codebase_policy.py` 会检查 factoryctl 能被 Python 3.8 语法解析、没有 CRLF、不 import mao。
6. 写 `tests/system/test_ctl.py`（至少 5 个），再跑验收。
