## 一套机制修复整条责任链

```mermaid
flowchart LR
    H[人: 目标和长期授权] --> O[持久目标与周期]
    O --> A[厂内 Agent: 观察与选择]
    A --> P[不可变计划与证据]
    P --> G[ChangeSet 治理业务扩展]
    P --> W[获授权的岗位]
    G --> W
    W --> R[Operator / Machine / Run]
    R --> F[持久结果与领域评价]
    F --> O
```

### 1. 用事务、去重和 fencing 保证驱动可靠

复用 SQLite、Mailbox、WakeQueue、LeaseStore；不再造一个业务队列。数据库事务内完成消息来源水位、去重键、邮箱插入及 wake 状态变更。邮件按持久 `enqueue_seq` 排序；延迟消息以 `not_before` 判可用，再按入队顺序取可用项，不能由随机 ID 决定。

AgentHost 的领批、running turn、消息 delivered 同事务；创建沙箱和启动 CLI 的异常也必须走统一结案。崩溃恢复只处理已失去有效所有权的轮次。agents 租约丢失立即停止新派发；在途结果提交检查持有代数，旧宿主不得结案、确认消息或发出后续动作。

### 2. 发布是一笔数据库决议，外部效果是可恢复投递

统一所有阶段的 safe-mode 和并发检查。candidate 槽归某个 ChangeSet；shadow/canary/active 观察期都占用发布额度。`active/previous/candidate`、ChangeSet 状态、转换需求解决和发布事件一起提交；Git refs 作为数据库指针的可重建镜像，用持久 outbox 同步。Git 和 SQLite 没有跨存储事务，不宣称瞬时原子；CLI 返回成功前完成 refs 同步，崩溃重启先同步再开放治理写入。

Registry 实际差异必须覆盖所有可加载 kind，未声明或不认识的结构差异直接拒绝。Agent 增改删正式进入 ChangeSet schema、风险事实和规则。权限、预算、定时与入站扩展按本规范的新风险表处理，不能用单独的文本声明降级。

### 3. 服务执行保留操作工，外部副作用保留身份

真实 factoryctl 支持服务协议；显式允许列表，默认拒绝额外 OpenAPI 操作。agent-cli 工位必须执行配置的操作工，由它经受控工具调用服务；脚本工位可走确定性 recipe。平台不能绕过声明的操作工封存。

每个外部操作先持久保存 operation key 和提交状态。已知 task_id 的失败只恢复 poll/fetch；fetch 已下载文件可复验。提交可能成功但响应丢失时，只有供应商幂等/查询协议能够解除不确定；否则进入 `outcome_unknown`，给厂内负责人一个可处理异常，禁止盲目重发。服务不存在普遍的 exactly-once 承诺。

### 4. 预算、结果和评价回到同一持久事实

预算以数据库账本为权威，重启不清零。预估保留、实际结算和释放使用事务；未知成本在账本明确标识，不能当 0。已有 job/line/agent 限额全部保留；宏观目标额外有总额和 UTC 日额。余额文件是可重建视图，CLI 读取它，模型计费事件可关联到账本。

每次 run 有稳定 request key 和发起者；终态和通知 outbox 同事务。Agent 能按 run_id 查询状态、节点、产物、错误、成本和回执。成功、失败、取消都送回同一岗位，重启和重复收集不产生新的逻辑通知。指标返回明确定义的样本、窗口和分母，不拿模型自评充当事实。

### 5. 目标周期组织 Agent 的工作，不替 Agent 做决定

目标、观察计划、候选、选择理由、产出和复盘保存为 M16 的普通业务资产（扩展 kind），引用已有 Bean、job、turn、run、receipt。M17 数据表只保存权限、周期、关联和水位，不重复保存一套业务载荷。

确定性控制面只在到期时可靠唤醒负责人、校验授权、执行计量、检查已有领域契约并记录状态。观察范围内有什么值得做、比较哪些候选、怎样组织岗位和业务工具，由厂内 Agent 完成。没有可做工作也要写证据和下一观察时间；没有证据不能假称“环境无变化”。

长期授权一次绑定精确目标版本、允许的岗位/产线及结构化扩展范围、领域评价契约、总预算/日预算、周期下限和有效期。它不是每个子任务的人工确认；撤销和过期即时阻断新动作。在范围内厂长通过复用 Mailbox 的可信 objective_dispatch 组织 worker（agent_send 保留协作），worker 通过既有 run_start 开工。厂长不取得任意 run_start；M15 临时运行卡的人确认保持原契约。新增工具能力走正常 ChangeSet，不允许业务 Agent 修改平台内核。

## 验收为何能阻止外层救场

总体验收只在开始时提供宏观目标、授权、环境和资料源，之后测试仅观察、推进时间与注入故障。发现候选、选目标、写计划、提结构变更、派工、查询结果与复盘，都必须来自真实启动的厂内 Agent 子进程经 MCP 调用。

需完成至少四个自主周期、至少两个不同输入所导出的具体工作，并覆盖空档后的新机会、失败后的调整、进程重启、已知外部任务继续 fetch，以及预算/授权阻断。状态、产物和领域 facts 都可核验；不能由测试直接写 run、调用 advance/propose 替厂长工作，不能直接改 `.factory`、Registry active 指针或代签。

离线脚本 Agent 只证明协议和接线，不能证明模型有发现和评估能力。M17 退出还需用户现有部署的真实 CLI + Docker 相同场景记录（至少四周期），固定 runtime/model/配置/目标/契约/成本和日志摘要。缺凭据或外部资源时本地开发可先完成确定性验收，但里程碑不能宣称已具备真实自主能力；实时通道只用现有资源，不新增控制面模型调用。
