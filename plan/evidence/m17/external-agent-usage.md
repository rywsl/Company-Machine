## 通用交付边界

应把外部 Agent 当作用户授权下的工厂操作者。可信管理员安装、配置隔离环境并给长期授权；受限外部操作者只检查、转达宏观目标、查看证据、转交真正需要人的事项；日常找具体工作、规划、派工、生产、评价和继续由厂内岗位完成。使用 skill 不给它额外修改平台源码、代签或写数据库的权限。用户若另行授权开发，按开发工作流处理，不能把开发职责混入普通运转能力证明。

三个相连的交付面都要存在：

1. **CLI 的可发现操作契约。** 顶层帮助区分控制面 factory、沙箱内 factoryctl、开发 harness/mrl；按用户任务给可到达入口。关键命令说明输入、前置、状态变化、作用域、输出和下一查询步骤；错误返回稳定类别、可观察阻塞和可行恢复动作。不能把“输出 JSON”当作流程完整。未知/未实现能力要可见，不编造成功，也不静默禁用审计。
2. **受版本约束的可复用 skill。** 面向安装与运行工厂的任务触发；从实际版本/help/能力开始，走预检、目标/授权交接、状态观察、诊断、恢复、结果验证。引用维护的规范和参考，避免复制整个命令手册；精确说明身份来源、付费副作用和人工权限边界。产品修复完成后发布草案的正式版本，并以同一能力来源同步 help/docs/skill。
3. **独立使用验收。** 新 Agent 只得到用户目标、发布的 CLI/help/skill、已授权的最小环境；不看产品源码，不得到预写业务动作或历史绕行答案。验证它能把业务交给厂内 Agent 自行完成，遇到缺资源能准确上报并恢复；不能通过外部 Agent 写业务 YAML/脚本、手动推进治理或代跑 line 掩盖自治缺陷。

当前已在operability.md §3冻结init/doctor/guide/capabilities、qualification及受限操作文件邮箱接口；continuity.md定义objective授权。它们尚未实施，不在当前c538768帮助中假称可用。skill历史草案仍只使用旧语法，M17-12发布时必须按新接口更新并验证；M15 talk不等于长期授权。

这些不是把所有 provider 逻辑塞入内核。通用层固定身份、权限、预算、状态、恢复与产物协议；领域差异通过声明和显式 adapter 承担。未接入能力不能以相似名称宣称已支持。

## 已冻结的使用验收包

- **U01 仅 CLI/help 的发现。** 验证可从顶层找到预检/启动、目标交接、观察、恢复、结果查询；用户只给宏观目标。缺环境、未启动岗位、等待授权、执行中、结果未知和失败必须可区分。不是正则搜 help 中几个词就算通过。
- **U02 使用 skill 的独立演练。** 仅给正式 skill 与 CLI，陌生真实 Agent 完成同样任务；记录走错命令、绕行、补提示与外部代做。静态 frontmatter 校验只证明格式，不能算成功。
- **U03 跨领域和跨 adapter。** 至少两个异质领域、两个 runtime adapter；固定同一平台源码摘要，替换合法声明/adapter/领域标准，宏观目标不包含具体步骤。一个领域不能只改名称但仍输出同一种视频。
- **U04 生命周期和故障。** 初装、保留数据重跑、重启恢复、失效依赖、权限阻塞、慢网络、外部结果未知和撤销；帮助引导到合法动作，不能引导删库、全量覆盖 Registry、关闭审计或盲目重复付费。
- **U05 角色边界。** 外部 Agent 将真正的人类事项交还用户；伪造 --by 标签不得当身份鉴权。核心权限测试和部署信任边界分开，不能承诺抵抗有管理 shell 的管理员修改。
- **U06 版本一致。** 公布的命令示例在真实安装包可执行；能力未实现明确显示限制；升级后 help、文档、skill、错误指导与 CLI 一致。M16 最终能力必须现场核对。

已有 C10 仍必须真实运行，不能由 U01/U02 的外部操作者代厂内 Agent 完成业务。离线协议与真实模型能力分别给结果。U01–U06已对应M17-12六个精确行为节点与M17-08真实四格witness，见closure.yaml。实际测试由任务实现；当前节点缺失会使执行器和最终门失败，不存在行为验收通过记录。
