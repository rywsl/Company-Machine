# M18 UI Demo 与本地 Web App 设计计划

## 1. 设计结论

M18 的交付目标是一个独立的本地 Web App 用户入口和可交互 UI demo。它服务于现有工厂控制面，不增加新的 Factory、Workarea、Operator 或 Machine 后端实体。

M18 的核心关系如下。

```text
人管理工厂和 Foreman
Foreman 创建和管理厂区、Operator、Machine、运行与恢复
Operator 负责项目执行、发现资源并主动请求资源
Machine 是 Operator 调用的开源项目、工作流或本地工具
```

Foreman 是工厂创造者。只要对应 Harness CLI 能运行，Foreman 就可以自动创建和修改拓扑、装配员工、处理资源请求、替换机器、修复运行并继续推进。UI 不用人工审批按钮限制这条链路。

人处理工厂级治理、Foreman 运行入口、宪法和 Foreman 无法继续处理的异常。普通运行问题由 Foreman 自治闭环处理。

M17 阶段门当前没有通过，因此 M18 文档是设计输入，M18 后端集成任务不得宣称已完成。

## 2. 体验原则

- 本地打开即进入看板，不出现登录和多用户概念
- 侧边栏只有看板、编排、资产、日志
- 侧边栏完全离屏，收起状态保留可拖动的 MAO 按钮
- 编排画布是所有拓扑和节点配置的主入口
- 工厂层只显示厂区
- 厂区层只显示 Operator 和 Machine
- Foreman 对话只在编排画布出现，并且与侧边栏独立
- 画布状态简洁，细节进入节点详情、Foreman 对话和日志上下文
- Foreman 可处理普通问题，不用人工审批打断自治流程
- 视觉沿用 creaibo-local 的浅色金属、石墨色、冷蓝色和柔和阴影

## 3. 视图和入口

### 3.1 看板

看板是默认页，用摘要帮助人了解工厂当前状态。

首屏卡片包括当前运行、Foreman 自动完成比例、正在处理的厂区、资源请求、不可恢复异常、资产、实例和宪法版本。卡片只提供摘要和进入上下文的动作。

看板中的人工边界卡片展示工厂、Foreman Harness、宪法版本和 Foreman 可用状态。点击后可以打开 Foreman 详情或宪法上下文。它不变成治理页面。

### 3.2 编排

编排页由画布、可选 Foreman 对话和可选节点详情组成。

工厂层默认显示两个或多个厂区节点以及显式边。边可以是物料流转、条件路径、默认路径或聚合关系。工厂层不显示厂区内部节点。

双击厂区节点进入厂区层。厂区层只显示 Operator 和 Machine。节点内容只表达它们对应的项目或职责，状态和细节进入右侧详情。

### 3.3 资产

资产页展示输入素材、输出资产和知识资产。列表显示名称、类型、封存状态、来源运行和来源节点摘要。点击后展示 Validation Epoch 和 Lineage 时间线。

### 3.4 日志

日志页展示运行时间线、Foreman 操作、自动验证、自动修复、资源请求、异常、ChangeSet、Epoch 和 Lineage。列表默认摘要，点击后显示上下文。

## 4. 画布数据模型

demo 和正式实现共用以下形状。

```js
{
  scope: "factory" | "workarea",
  id,
  title,
  nodes: [
    {
      id,
      type: "workarea" | "operator" | "machine",
      group,
      label,
      position: { x, y },
      status,
      metadata
    }
  ],
  edges: [
    {
      id,
      source,
      target,
      kind: "material" | "condition" | "default" | "aggregate",
      condition,
      status,
      metadata
    }
  ]
}
```

工厂层数据中 `nodes` 的 `type` 只能是 `workarea`。厂区层数据中 `nodes` 的 `type` 只能是 `operator` 或 `machine`。类型约束在 mock 数据、渲染器和浏览器验收中同时检查。

节点坐标只用于阅读和整理。节点位置不参与执行，也不写入后端业务状态。

## 5. Harness CLI 设计

Foreman 和 Operator 都在画布节点详情中选择 Harness CLI。demo 提供以下示例项。

- Claude Code
- Codex
- DeepSeek Harness
- Kimi CLI
- Zcode
- Pi
- 本地发现的 Harness
- 自定义 Harness

示例项用于表达产品能力，不能被实现为固定的封闭枚举。正式适配器读取本地能力描述，至少包含名称、版本、角色、启动方式、输入输出协议、持续会话、工具调用、恢复能力和可用状态。

UI 显示当前选择和能力摘要。遇到未识别 Harness、版本不匹配或启动参数不完整时，Foreman 进入适配异常并尝试修复或替换，页面保留继续处理入口。

Foreman 节点详情重点显示当前 Harness、版本、持续会话和创建修改能力。Operator 节点详情重点显示当前 Harness、负责项目、输入输出契约、验证结果和最近资源请求。

## 6. 关键交互

### 6.1 MAO 按钮和侧边栏

MAO 按钮使用 Pointer Events 拖动。拖动结束按照指针的水平位置决定左侧或右侧停靠，垂直位置限制在视口范围内。点击按钮打开侧边栏，拖动不触发导航。

侧边栏通过整体滑入和滑出实现离屏状态。它不会缩小成窄条，也不会改变 Foreman 对话的开关状态。

### 6.2 画布拖动

画布由视口、世界层、SVG 边层和节点层组成。节点拖动、画布平移和缩放使用同一套 Pointer Events 状态机，但节点事件必须阻止冒泡。

节点拖动使用当前缩放比例换算指针位移，只修改当前节点位置。拖动结束静默保存。画布平移只修改当前层级的 pan，缩放只修改当前层级的 zoom。

每个层级保存独立的布局键。刷新后根据节点 ID 恢复仍然存在的坐标，删除节点的坐标自动丢弃。

### 6.3 双击进入厂区

工厂层厂区节点支持双击进入。进入后替换当前画布内容，只保留当前厂区的 Operator 和 Machine。返回工厂时恢复工厂层状态。

### 6.4 Foreman 对话

Foreman 面板默认隐藏。用户输入目标后，demo 用 mock 消息展示解析、创建、装配、检查、运行、验证和修复。自动应用后直接更新画布，不显示批准或确认运行按钮。

Foreman 可处理以下上下文。

- 创建新的厂区
- 装配或替换 Operator
- 装配或替换 Machine
- 连接调整
- Harness 能力检查
- 资源请求
- 自动验证
- 自动修复
- 运行恢复
- 机器交付角色判断

### 6.5 资源请求

Operator 节点详情显示最近资源请求摘要。用户点击后进入资源上下文，看到请求来源、用途、使用范围、Agent 生成的检查项和当前状态。Foreman 可以继续处理请求，用户不需要提前为每个节点填完密钥。

### 6.6 节点详情

节点卡片保持简洁。初始详情显示名称、类型、对应项目和短状态。展开后显示 Harness、输入输出契约、开源项目、Git 或工作流文件、最近验证和资源请求。

Machine 详情不提供 sink 开关。交付语义由 Foreman 根据项目配置和实际执行关系判断。

## 7. 状态和异常

普通状态使用就绪、运行中、验证中、修复中和已完成等短标签。不可继续的问题使用 Foreman 不可用、资源请求、适配异常、宪法冲突、修复耗尽、实例崩溃、条件错误和连接无效等上下文。

只要 Foreman Harness 可用，异常默认进入 Foreman 自动处理链路。人看到的是当前处理阶段、来源和恢复结果，不看到审批队列。

## 8. 实施切片

### M18-01 本地 Web App 壳

交付独立本地页面、四入口、无登录模型、离屏侧边栏、可拖动 MAO 按钮、本地偏好恢复和传统顶部导航清理。

### M18-02 两层拓扑和稳定画布

交付显式 nodes/edges 图模型、工厂层厂区聚合、厂区层 Operator/Machine 过滤、双击进入、返回恢复、节点拖动、画布平移、缩放、适应画布和布局持久化。

### M18-03 Foreman 和 Harness 选择

交付编排画布内 Foreman 对话、自动应用和自治状态。交付 Foreman 与 Operator 的 Harness 选择、能力摘要、未知适配器状态和资源请求上下文。

### M18-04 业务上下文

交付节点详情、看板、资产、日志、宪法上下文、资源请求上下文、ChangeSet/Epoch/Lineage 时间线和异常回到画布的入口。

### M18-05 集成回归

交付本地 Web App 启动路径、浏览器回归、布局恢复、控制台错误清理和临时验证产物清理。纯 demo 作为交互基准，不替代后端能力验收。

## 9. 验收矩阵

| 维度 | 验收 |
|---|---|
| 本地入口 | 打开后直接进入看板，无登录和用户入口 |
| 导航 | 只有看板、编排、资产、日志 |
| MAO | 可拖动，左右停靠和垂直位置恢复 |
| 工厂层 | 只有厂区节点和显式边 |
| 厂区层 | 只有 Operator 和 Machine |
| 层级 | 双击进入，返回互斥，布局恢复 |
| 画布 | 节点拖动不跳动，平移、缩放、适应画布可用 |
| Foreman | 只在编排页出现，可独立开关，可自动应用 mock 结果 |
| Harness | Foreman 和 Operator 都可选择，支持发现和自定义空间 |
| 自治 | 普通问题由 Foreman 继续处理，不出现普通审批按钮 |
| 资源 | Operator 主动请求，Foreman 可处理，秘密值不进普通 UI |
| 业务模块 | 看板、资产、日志、宪法、运行、实例、ChangeSet、Epoch、Lineage 可达 |
| 清理 | 根目录没有临时截图、Playwright 输出和浏览器缓存 |
| 控制台 | 浏览器无未处理异常 |

## 10. 灵活性约束

M18 冻结用户可见边界、节点类型和核心自治逻辑。实现可以在以下方面调整。

- 原生 DOM/SVG 或 React Flow
- 本地页面路由和控制面适配方式
- Harness 能力描述的字段扩展
- 适配器发现和注册机制
- 详情面板的渐进式布局
- 状态颜色、图标和文案
- 后端运行语义变化后的聚合映射

遇到现有后端没有直接对应的 UI 事实时，优先展示来源、当前状态和 Foreman 处理进度，并保留后续适配空间。不要为了填满画布增加后端不存在的节点或控制能力。
