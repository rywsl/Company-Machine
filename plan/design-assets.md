# M16：把工厂的业务能力留在数据里

## 已确定的边界

交付对象是整套工厂能力：编排、岗位、知识、技能、工具、材料、中间结果、产品、显式进度与证据，不只是 prompt 或几个 skill。平台内核是版本化运行依赖；账号、凭据、许可证、设备和外部服务是显式资源绑定。完整私有检查点与可交易的脱敏移交包具有不同用途和格式。

用户要求最少改动、可扩展、鲁棒，厂长要有足够的工作空间；不能做成影子模式，不能为了资产化持续增加模型工作。本计划只设计 M16，不在设计交付时实现产品、启动任务或登记完成。

## 管理原则如何落到接口

| 管理原则 | 在本项目中的约束 |
|---|---|
| 标准作业与例外管理 | 正式知识有版本、适用范围和反例；例外保留为证据，由厂长提出候选，不直接覆盖标准 |
| 标准制定与执行分工 | 人初始化领域验收契约，厂长在契约内自主选样例、组织任务、评估和晋升；不能临时改题再宣布通过 |
| 组织记忆与人员替换 | 企业记忆是目录、交接、队列、物料和回执；原生 CLI 私有会话不承担唯一业务真相 |
| 变更管理与可追溯性 | 新版本加新证据，CAS 更新正式指针；失败保留原件和旧能力，不能用“压缩”偷渡删除 |
| 单件流与过程质控 | 正常生产直接产生验证证据；新岗位接着做真实任务，不复制全量任务、不长期养第二班生产者 |
| 配置管理与资源清单 | 资产闭包、实际运行依赖、环境和外部资源一起固定；静态文件校验与业务能力验收分别报告 |

这些是设计依据，不声称管理学本身已经证明 Agent 的能力。真正的能力判定仍要靠领域契约与新的实际执行。

## 最小实现面

保留现有 Bean/CAS、Registry/MRL、Runner/Gate、缓存、邮箱、预算与审批、ChangeSet、回执、backup。只增加三组职责：

- `mao.assets`：内容地址目录、依赖、保留根。载荷仍在现有 Warehouse；不新增 MRL kind。
- `mao.learning`：已授权契约、真实执行绑定、知识指针和接管证明。MRL 对已记录事实求值，不创建自己的执行器。
- `mao.packages`：复用 backup 的完整冷检查点；由明确披露的派生资产重建移交包。交易市场不在本项目。

一份追加式迁移 `042_assets.sql`；不改变 `render_brief` 和 `KeyMaterial` 签名。操作员用普通输入端口取得业务材料，材料 hash 已在缓存键内。常驻 Agent 每轮只读一个固定版本上下文清单，提示正文只带索引。补齐常驻厂长对现有 agent_send/remind 的调用，使它能用原邮箱安排操作员验证；不新授予直接启动任意产线的权限。

启用为 `factory.json.assets` 显式 opt-in。旧工厂和已有验收不因新功能改变行为。新工厂启用后，安全交接和证据保护是硬约束。M16 不提高权限，结构变更仍走现有治理。厂长可以创建任意业务资产、工具、流程、测试候选，使用已授权契约进行多次验证；无需逐条让人审批知识。只有初始化或更改验收标准、用户指令来源的授权留在人的操作面。

## 三条生产闭环

### 资产到移交

厂长将业务文件产成 Bean、登记它们的依赖，维护整厂 factory 资产与外部资源说明。停机窗口里做完整检查点，保存全部现存数据并明确历史保留缺口。要出售时先产生脱敏的新资产和干净 Registry 树，再从检查点选择闭包、绑定披露审核，重建公开包。

公开包没有卖家的数据库、Git 历史、私有对话、凭据和活跃订单。它包括完整编排与选定的相关业务数据；不能转让的资源必须显式替换或由买家绑定。公开包中的历史事实不冒充买家环境的能力证明。买家导入时校验与重新准入物料，随后用自己的岗位、模型和资源验证。哈希能证明内容一致，不能自动证明隐私、权利或收益。

### 经验到正式知识

候选含 claim 分类、边界、来源与失效条件。试验先固定 target、契约、环境和事件水位，再让下一个适用的真实任务使用它；正常工作的结果直接作为证据。厂长只收集可核验的 job/turn 和领域 facts，不另开一次“判断总结好不好”的模型循环。

通过后 CAS 更新该岗位该 key 的正式版本，下一轮才生效。失败不覆盖旧知识。用户规则/偏好是授权来源的问题，不拿实验“证明”用户偏好；directive 必须有人对确切版本授权。相关依赖变化显示 stale，但不自动跑整厂评估。

### 交接到替换

日常上下文轮换仍只有已有的一次 handoff CLI。启用 M16 后写临时结构化交接，成功固化后才清 session；失败保留旧状态、暂停并通知，不做无穷重试。

真正替换时从固定交接建立全新业务工作区与私有 CLI home，旧工作区不挂进去。同一个岗位继续消费原有邮箱；不存在第二条生产通道。代表任务要覆盖正常、例外、恢复、不确定性，厂长还要覆盖计划、预算、变更判断和交接。能力证明绑定实际模型、工具、环境、知识与交接版本。失败暂停；已经完成的消息和外部回执不回滚或重新派发。

## 算力与一致性的取舍

- 没有额外模型服务、定期影子任务、自动周期压缩或强制模型评审。
- 未启用没有资产扫描；启用后平时是索引查询、固定清单和少量执行元数据。不可变闭包按 hash 缓存。
- 只在明确的替换/相关依赖变化/交付事件验证受影响能力，正常真实工作可充当验证。昂贵但未变化的上游材料可复用。
- 完整快照是停机动作，SQLite 写屏障与 GC 互斥保证一致性。额外成本主要是一次 I/O；不以不一致的在线复制省性能。
- Postgres/S3 的一致性快照、真实设备现场/交易账户持仓的外部固化留给相应适配器。缺少状态就明确不能完整恢复，禁止默默降级。

## 实施顺序与必须守住的接口

| 任务 | 完成后的可审查结果 |
|---|---|
| M16-01 | 不可变资产目录、闭包、受保护证据与显式释放 |
| M16-02 | 固定领域契约、真实执行证据、原子知识晋升与 stale |
| M16-03 | 成功后才轮换的交接、全新私有状态的单岗位接管 |
| M16-04 | 包含业务状态的完整冷检查点与安全恢复 |
| M16-05 | 从明确披露闭包重建的移交包、买家资源绑定与准入 |
| M16-06 | 厂长/Agent/CLI 操作面接通，完整离线端到端证明 |

精确接口、状态转换、错误码、文件格式、验收函数见 `spec/system/assets.md`。实现者不得自行增加后台压缩器、绕过 ChangeSet 激活工具、降低领域契约，或为了通过验收把资产自评当运行证据。
