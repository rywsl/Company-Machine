# M15-03 受阻：验收用 agent 的 run_start 却要求未知工具

- 时间：2026-11-15
- 任务：M15-03 运行确认
- 现象：`uv run python tools/harness.py pytest tests/acceptance/m15` 中 `test_propose_run_records_card_only` 失败。`world.mcp("run_start", ...)` 返回成功的 JSON-RPC result，`structuredContent.result` 为新 run `r-0001` / `PENDING`。断言要 `reply["error"]["message"] == "unknown tool"`。同一次运行里另外 20 个 M15 测试通过。
- 规范依据：`spec/system/talk.md` 第 7 章，原文：“厂长调用 `run_start` 仍是未知工具”。同文件第 8 章：“`run_start` 仍只属于 agent 角色”。`spec/system/mcp.md` 的 agent 工具含 `run_start`。夹具 `tests/acceptance/m13/agent_world.py` 的 `World.mcp` 以 `role="agent"` 调用。`tests/acceptance/m13/test_m13_04_context.py` 用同一个 `w.mcp("run_start", ...)` 并要求成功。
- 我的理解：A：按字面让这次 `world.mcp("run_start")` 变成未知工具。agent 就不再有 `run_start`，M13 验收和“`run_start` 仍只属于 agent”一起失败。B：厂长工具表不包含 `run_start`（已经如此），agent 仍可调用。这符合规范正文，但过不了这条用 agent 入口写成的断言。
- 已经尝试：人已把断言改成厂长会话 `_foreman_raw`。`accept M15-03` 的 acceptance 与 regress 通过（6/6，回归 total=1626，failed=0）。随后 lint I001 与 `ruff format` 失败，因为该文件顶层函数之间少一个空行。再改空白仍被 hook 拒绝。没有绕过 hook，没有 `lock --update`。
- 建议：人把该断言改成厂长会话调用 `run_start`（例如 `foreman_call`），或改成检查 agent 调用仍然成功。不要从 agent 工具表删掉 `run_start`。
