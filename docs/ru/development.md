# Разработка

Код, `spec/` и приёмочные тесты можно изменять в порядке, который нужен для проверки. Спецификацию не требуется коммитить до реализации.

## Проверка перед отправкой

Перед commit или push выполните:

```bash
uv run python tools/harness.py verify
```

`verify` проверяет коды ошибок и функции стандартной библиотеки MRL, factory profile, структуру глав `spec/system` и двустороннее соответствие главы 7 каталогу `tests/acceptance/`. Затем запускаются связанные приёмочные тесты, MRL conformance, MRL coverage и тесты политики кода. В связанных приёмочных тестах не должно быть ошибок, падений или пропусков.

## Рабочий процесс

Если код, спецификация и тесты расходятся, исправьте расхождение в том же изменении и снова запустите `verify`. Текущий процесс не требует брать или запускать задачи, проходить stage gates, поддерживать состояние задач, использовать lock защищённых файлов, создавать артефакты ревью или устанавливать PreToolUse- и Git-hook. Исторические материалы в `plan/tasks/`, `plan/journal/` и файлы этапов сохраняются для контекста, но не являются текущей точкой входа и не читаются `verify`.

## Технические правила

Не добавляйте зависимости, не вызывайте LLM API из control plane, не используйте `shell=True` и не ослабляйте тесты ради проверки. Не помещайте учетные данные в логи, commit или ответы. Сохраняйте независимые изменения. Выполняйте commit и push только по явному запросу.
